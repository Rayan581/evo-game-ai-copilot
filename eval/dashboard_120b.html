How a cycle works

The same loop runs every time you call evo cycle. The program then exits; the next cycle starts from evo.db alone, which is what "persistent memory" means here.

  1. 1IngestRead new run folders: config, scores, logs. Validate and hash every file.
  2. 2AnalysePlain code scores each run, groups seeds by config and compares with the baseline (bootstrap CI).
  3. 3BriefBuild the planner's briefing from memory: facts, hypotheses, lessons, past decisions, rejections.
  4. 4DecideThe planner (LLM or offline rules) picks ONE action and cites evidence.
  5. 5GateCode checks the action: approved settings, budget, real evidence, no repeats. It can refuse.
  6. 6ActAllowed actions run. New training runs wait for your approval.
  7. 7SaveEvery step, tool call and memory read/write is written to evo.db. Up to 8 steps, then end.
